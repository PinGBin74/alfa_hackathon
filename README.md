# Alfa News Insights

Сервис персонализированной новостной аналитики для руководителей крупного бизнеса внутри интернет-банка
Альфа-Бизнес (кейс хакатона «Альфа Будущее», трек «Новостная аналитика для принятия бизнес-решений»).

Сервис определяет бизнес-контекст компании по данным банка, отбирает из потока новостей события, важные именно для неё,
и готовит разбор: что произошло, почему это важно компании, какие риски и возможности, что можно сделать и как событие
оценивает Альфа-Банк. Каждый вывод помечен: факт из новости, позиция банка (со ссылкой на страницу материала), вывод AI
или признак компании. Разбор готовит собственный агент: план, инструменты, единый контекст, самопроверка другой
моделью и правка.

## Что внутри

| Критерий кейса | Где в решении |
|---|---|
| 01 Бизнес-контекст и отбор событий | профиль компании (`services/client_profile.py`, граф контрагентов `services/counterparty_graph.py`), персональная лента (`services/ranking.py`), экран «Профиль компании» |
| 02 Позиция банка отделена от AI | `bank_position` только из аналитики банка с цитатой страницы, `ai_inference` отдельно; в интерфейсе - разные «голоса» |
| 03 Связь с первоисточниками, минимум ошибок | у каждого вывода источник; проверка чисел и ссылок правилами + фактчекер DeepSeek; первоисточник открывается в боковой панели (страница материала банка с цитатой, PDF, статья) |
| 04 Новости, которых не было в базе | «Разобрать любую новость по ссылке»; eval на отложенном наборе реальных новостей (`docs/ml.md`, раздел 6) |
| 05 Полный сценарий | вход -> главная -> лента -> разбор -> вопрос -> первоисточник |
| 06 Содержательная интерпретация | несколько факторов, контрагенты, группа, ВЭД, роль пользователя |
| 07 Масштабирование и сопровождение | `docs/scaling.md` |
| 08 Точка входа на главном экране | пункт меню «Новостная аналитика» на всех экранах (со счётчиком важных событий) и блок на главной |
| 09 Взаимодействие с аналитикой | чат по разбору (другой разрез, детали, первоисточник), фильтр ленты по фактору |
| 10 Агентная логика | `backend/app/agent/`: планировщик, инструменты под allowlist, контекст, самопроверка и адаптация; ход агента виден в интерфейсе во время генерации |
| 11 Трассируемость | вкладка «Как получен разбор»: признаки компании, все шаги, модели, время, стоимость, сырые данные шагов (`agent_traces`) |
| 12 Мониторинг качества | экран «Качество AI», `GET /api/feedback/metrics`, оценки пользователей, `eval/` (`docs/monitoring.md`) |

## Архитектура

```
RSS-ленты, новость по ссылке ─> ingestion: текст, дедупликация, разметка Gemma ─┐
PDF аналитики банка ─> текст/OCR, позиции банка с цитатами (positions.json) ────┼─> Postgres (+pgvector)
CSV банка (компании, платежи) ─> профиль, группа, граф контрагентов ─────────────┘          │
                                                                                            v
           лента: детерминированный скоринг клиент x новость x роль (без LLM, с причинами ранга)
           разбор: план (Gemma) -> инструменты -> контекст -> черновик (GLM) -> проверка (правила + DeepSeek) -> правка
                                                                                            │
                    FastAPI (backend, :8000)  <── /api ──  frontend: имитация Альфа-Бизнес (:3000)
```

Подробнее: `docs/architecture.md` (компоненты, API, безопасность), `docs/ml.md` (ML и агент), `docs/data_model.md`.

## Требования к окружению
- Docker и Docker Compose (основной способ запуска).
- Для разработки без Docker: Python 3.12 и [uv](https://docs.astral.sh/uv/), Node.js 20+, Postgres 16 с pgvector.
- Ключ к LLM-прокси организаторов (`LLM_API_KEY`): без него работают вход, лента, профиль, готовые разборы и метрики,
  а новые разборы, чат и разметка новостей - нет.
  
### ⚠️ Особенности развертывания на старых CPU (x86-64-v1)

Свежие версии пакета `numpy` (2.x) по умолчанию требуют поддержки процессорных инструкций архитектуры **x86-64-v2** (SSE4.2, POPCNT). Если ваше серверное окружение или гипервизор виртуализации выдает ошибку:
`RuntimeError: NumPy was built with baseline optimizations (X86_V2) but your machine doesn't support (X86_V2)`

**Решение, примененное в репозитории:**
Зависимости бэкенда строго зафиксированы на `numpy==1.26.4`. При изменении состава пакетов в `pyproject.toml` обновление замок-файла необходимо производить через окружение с поддержкой системных вызовов (например, `uv:0.9.5-debian`):
```bash
docker run --rm -v \$(pwd)/backend:/work -w /work ghcr.io/astral-sh/uv:0.9.5-debian uv lock
```

Версии зафиксированы: `backend/uv.lock`, `frontend/package-lock.json`, теги образов в Dockerfile.

## Запуск
```bash
cp .env.example .env     # вписать LLM_API_KEY и POSTGRES_PASSWORD (любой), для стенда - JWT_SECRET
make up                  # db + backend + worker + frontend; миграции применяются при старте backend
make seed                # исходные CSV кейса из data/raw + тестовые учётки
#   или, без исходных данных: make seed-demo  (синтетические компании и платежи + 16 демо-новостей с разметкой)
make ingest              # аналитика банка в БД и разовый сбор новостей из RSS (~3 ₽ на разметку ~80 новостей)
make warmup              # заранее подготовить разборы по верху лент тестовых пользователей (~0,8 ₽ за разбор)
```

Без `make` (на Windows его обычно нет) - те же шаги через Docker Compose, команды одинаковы в PowerShell и bash:
```powershell
cp .env.example .env                 # вписать LLM_API_KEY и POSTGRES_PASSWORD
docker compose up -d --build
docker compose exec backend python -m app.db.seed
docker compose exec backend python -m app.db.seed --dir data/synthetic --news data/synthetic/news.jsonl   # вместо предыдущей, без исходных CSV
docker compose exec backend python -m app.ingestion.scheduler --once
docker compose exec backend python -m app.agent.warmup --top 2
```
Остановить: `docker compose down` (данные БД сохраняются); удалить вместе с данными: `docker compose down -v`.

- Интерфейс: http://localhost:3000
- API и Swagger: http://localhost:8000/docs (схема также в `contracts/openapi.json`)
- Worker собирает новости каждые 30 минут; без `make warmup` разбор готовится при первом открытии события (1-1,5 мин).
- Без `LLM_API_KEY` экран события сообщает, что модели не настроены (API отвечает 503); вход, лента и профиль работают.

Исходные CSV кейса (`df_Uid_data_hack.csv`, `df_Fid_Uid_link_hack.csv`, `df_Uid_payment_hack.csv`) кладутся в `data/raw/`
(в git их нет).

### Разработка без Docker
Команды - из корня репозитория: так читаются `.env` (адрес БД собирается из `POSTGRES_*`, хост по умолчанию `localhost`) и `data/`.
```bash
(cd backend && uv sync)
export PYTHONPATH=backend
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head
backend/.venv/bin/python -m app.db.seed --dir data/raw          # или --dir data/synthetic --news data/synthetic/news.jsonl
backend/.venv/bin/python -m app.ingestion.scheduler --once      # аналитика банка и сбор новостей
backend/.venv/bin/uvicorn app.main:app --port 8000
cd frontend && npm ci && npm run dev                            # http://localhost:3000, /api -> http://127.0.0.1:8000
```
Тесты и линтер: `cd backend && .venv/bin/python -m pytest -q && .venv/bin/ruff check app tests`;
типы фронтенда: `cd frontend && npm run typecheck`.

## Сценарий проверки
1. Откройте http://localhost:3000 и войдите как `cfo_demo`. На главной - блок «Новостная аналитика» с тремя
   самыми важными для компании событиями; пункт меню «Новостная аналитика» доступен с любого экрана.
2. Откройте ленту. У каждой новости - место в ленте, значимость и причины («есть кредиты в Альфа-Банке: ставка
   определяет стоимость обслуживания...»). Справа - признаки компании, по которым подобрана лента.
3. Переключите компанию в шапке (U_9250 -> U_177581): лента меняется. Войдите под другой ролью той же компании
   (`accountant_demo` для U_177581) - меняется порядок.
4. Откройте событие. Если разбор ещё не готов, видно, как агент работает: план, поиск в аналитике банка, граф
   контрагентов, черновик, проверка, правка. Готовый разбор отвечает на шесть вопросов кейса; пометки слева показывают,
   где факт из новости, где позиция Альфа-Банка, где вывод AI и какие признаки компании использованы.
5. Нажмите на ссылку «Альфа-Банк» у позиции банка: откроется страница материала с дословной цитатой, пометкой,
   если прогноз позже обновлён, и PDF. Ссылка «Новость» открывает текст и статью на сайте источника.
6. Задайте вопрос справа (например, «Покажите влияние в разрезе контрагентов»): ответ со ссылками на источники.
7. Вкладка «Как получен разбор»: признаки компании с весами, все шаги агента, модели, время и стоимость.
8. В ленте вставьте ссылку на любую свежую деловую новость в поле «Разобрать любую новость по ссылке» - статья
   пройдёт тот же конвейер и сразу откроется её разбор.
9. Оцените разбор («Разбор был полезен?») и откройте «Качество AI»: метрики проверки, связи с источниками,
   обратной связи, стоимости и бюджета.

## Конфигурация
Все переменные описаны в `.env.example`.

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | OpenAI-совместимый прокси организаторов и ключ команды |
| `LLM_MODEL_*` | ID моделей в прокси (только модели из Приложения 3), роли моделей - `docs/ml.md`, раздел 5 |
| `DAILY_BUDGET_RUB` | мягкий дневной лимит расходов на LLM (жёсткий лимит ключа - 500 ₽/день); при исчерпании новые разборы недоступны (429), остальное работает |
| `POSTGRES_*`, `DATABASE_URL` | БД: адрес собирается из `POSTGRES_USER/PASSWORD/DB/HOST/PORT` (в Docker хост - `db`); `DATABASE_URL` - задать адрес целиком |
| `POSTGRES_PASSWORD` | обязателен: пароль БД (значения по умолчанию нет, без него compose не стартует) |
| `JWT_SECRET`, `JWT_TTL_MINUTES` | подпись токенов входа; при `APP_ENV=prod` backend не стартует с ключом короче 32 байт или из шаблона |
| `APP_ENV` | `prod` скрывает список тестовых учёток |
| `INGEST_INTERVAL_MINUTES`, `NEWS_MAX_AGE_DAYS` | период сбора новостей и окно ленты |

Эмбеддинг-модели в списке кейса нет, поэтому поиск лексический (BM25 с русской нормализацией), см. `docs/ml.md`.

## Данные
- `data/raw/` - исходные CSV кейса (не в git).
- `data/synthetic/` - синтетические CSV в том же формате и демо-новости: те же 5 демо-клиентов с близкими признаками
  (генератор `python -m app.db.synthetic`, `docs/data_model.md`).
- `data/bank_analytics/` - материалы Альфа-Банка (Приложение 2), их текст (`text/`, в том числе OCR сканов) и
  извлечённые позиции банка с дословными цитатами (`positions.json`).
- `data/test_accounts.json` - тестовые учётки.

## Качество (eval)
```bash
cd backend
.venv/bin/python ../eval/run_eval.py ranking [--set real|holdout]    # офлайн: ранжирование против разметки 0/1/2
.venv/bin/python ../eval/run_eval.py classify [--set holdout]        # офлайн: разметка новостей Gemma против эталона
cd ..
# живые (нужны БД с данными и ключ; из корня репозитория - читаются .env и data/)
PYTHONPATH=backend backend/.venv/bin/python eval/run_eval.py insights [--set real|holdout] --judge
PYTHONPATH=backend backend/.venv/bin/python eval/run_eval.py collect --set holdout   # собрать новый набор реальных новостей
```
Наборы: synthetic (регрессия логики), real (подбор правок), holdout (проверка правок на новостях, которых не было при
подборе). Последние результаты: персональная лента на holdout nDCG@5 0,754 против 0,657 у сортировки по важности и
0,157 у хронологической; разбор - 0,7-1,2 ₽ и 55-100 с. Подробно - `docs/ml.md`, раздел 6; отчёты - `eval/reports/`.

## Безопасность
Разграничение доступа по ролям и компаниям (JWT), тексты новостей и документов передаются моделям как данные внутри
`UNTRUSTED_SOURCE` и сканируются на инъекции, инструменты агента - allowlist и только чтение, все обращения к
инструментам и моделям журналируются в `agent_traces`, защита от SSRF при загрузке статьи по ссылке, дневной бюджет LLM.
В промпты попадают только обезличенные признаки компании. См. `docs/architecture.md`.
