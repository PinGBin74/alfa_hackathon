# Архитектура

## Компоненты
- **Postgres + pgvector**: компании, платежи, новости, чанки аналитики банка, инсайты, трассы агента, расход токенов, обратная связь.
- **Backend (FastAPI)**: API, профиль клиента, граф контрагентов, ранжирование, агентный оркестратор.
- **Worker**: периодический сбор новостей, загрузка аналитики, классификация, дедупликация.
- **Frontend** (`frontend/`, React + Vite, в Docker - nginx): имитация интернет-банка Альфа-Бизнес. Точка входа в
  сервис - пункт меню «Новостная аналитика» (виден на всех экранах, со счётчиком важных событий) и блок на главной.
  Экраны: вход по тестовой учётке, главная, персональная лента (+ разбор новости по ссылке), разбор события
  (живой ход агента, разбор по шести вопросам кейса с пометками «новость / Альфа-Банк / вывод AI / признак компании»,
  первоисточники, чат, трасса, оценка), профиль компании, качество AI.

## Поток данных
1. Ingestion: источники -> очистка -> дедупликация -> классификация (лёгкая LLM) -> БД.
2. Запрос ленты: профиль клиента + граф -> скоринг новостей (`services/ranking.py`).
3. Запрос инсайта: `agent/orchestrator.py` -> план -> инструменты -> черновик -> самопроверка -> повтор при замечаниях.
   Разбор готовится 1-1,5 мин; `services/insight_jobs.py` задаёт trace_id до старта, поэтому фронтенд показывает шаги
   агента по мере записи в трассу (`GET /api/insights/{client_id}/{news_id}/progress`), а повторный запрос того же
   разбора ждёт первый прогон. Готовый разбор кэшируется по (компания, новость, роль).
4. Результат: JSON по `contracts/insight.schema.json` с разделением `confirmed_facts` / `bank_position` / `ai_inference`.

## Агентная логика (стр. 7 задания)
| Требование | Реализация |
|---|---|
| Планирование | `agent/planner.py` |
| Инструменты | `agent/tools/registry.py` (allowlist) |
| Контекст | `agent/state.py` |
| Самопроверка и адаптация | `agent/verifier.py` + цикл в `orchestrator.py` |

## Безопасность (п. 6 ограничений)
| Механизм | Где |
|---|---|
| Разграничение прав | `security/rbac.py` (JWT, роли, доступ к компаниям) |
| Защита от prompt injection | `security/injection_guard.py` |
| Allowlist инструментов | `security/tool_allowlist.py` |
| Журналирование обращений | `observability/tracing.py` -> `agent_traces` |
| Контроль бюджета | `services/token_budget.py` |
| Чувствительные данные | данные обезличены; в промпты идут только нужные признаки |

## API (Swagger: `/docs`, схема: `contracts/openapi.json`)
| Метод | Назначение |
|---|---|
| `POST /api/auth/login`, `GET /api/auth/me`, `GET /api/auth/demo-accounts` | вход по тестовой учётке, роль, доступные компании |
| `GET /api/clients`, `GET /api/clients/{id}/profile` | компании пользователя и бизнес-контекст (признаки, группа, место в отрасли, граф контрагентов) |
| `GET /api/feed/{client_id}` | персональная лента с причинами ранга и ссылкой на готовый разбор |
| `POST /api/news`, `GET /api/news/{news_id}` | новость по ссылке (тот же конвейер, что у RSS) и карточка новости |
| `POST /api/insights/{client_id}/{news_id}`, `GET .../progress`, `GET /api/insights/{id}`, `GET /api/insights/{id}/trace` | разбор, ход генерации, трасса |
| `POST /api/chat` | уточняющий вопрос к разбору (с историей разговора), ответ со ссылками на источники |
| `GET /api/analytics`, `GET /api/analytics/{doc}/pages/{page}`, `GET /api/analytics/{doc}/file` | первоисточник позиции банка: цитаты страницы, текст, PDF |
| `POST /api/feedback`, `GET /api/feedback/metrics` | оценка разбора, метрики качества |
| `GET /api/meta` | справочники: факторы, классы ОКВЭД2, роли |

## Роутинг моделей
Gemma 4 26B A4B: разметка новостей и план агента. GLM-5.3-Flash: черновик инсайта. DeepSeek-V4.1-Flash: фактчекинг
черновика (другая модель, чем автор) и извлечение позиций банка. Qwen3.6 35B A3B: уточняющие вопросы. Kimi-K2.6: судья в
eval. Qwen3-VL: OCR сканов. ID моделей - `app/config.py` / `.env.example`, профили вызова - `agent/llm_client.py`,
обоснование выбора - `docs/ml.md`, раздел 5.
