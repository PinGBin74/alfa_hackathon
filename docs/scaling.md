# Масштабирование и сопровождение

- **Новый источник новостей**: подкласс `NewsSource` в `ingestion/sources/`, регистрация в `SOURCES`.
- **Новая отрасль**: расширить словарь отраслей/событий (`ranking.py`, промпт классификации); код агента не меняется.
- **Новый тип клиентов**: новые признаки в `ClientProfile` + веса в `ranking.WEIGHTS`.
- **Новые аналитические материалы**: положить PDF в `data/bank_analytics/` (скан без текстового слоя - сначала
  `python -m app.ml.bank_positions ocr --pdf <файл>`), извлечь позиции банка
  `python -m app.ml.bank_positions --docs <файл>` (дописывает `positions.json`), затем `make ingest`.
- **Сопровождение**: миграции Alembic, версионируемые промпты в git, eval-набор в `eval/`.

## Горизонтальное масштабирование
- **Лента дешёвая**: скоринг детерминированный, без LLM (~1 мс на пару клиент x новость), считается на лету по
  последним 500 новостям окна; при росте потока - предрасчёт причин ранга по новости и индекс по факторам/отраслям.
- **Разбор дорогой** (0,6-0,8 ₽ и 50-75 с): кэш по (компания, новость, роль) в `insights`, прогрев верха лент
  (`python -m app.agent.warmup`), генерация только по запросу пользователя. Сейчас прогоны идут в потоках одного
  процесса API, реестр идущих прогонов - в памяти (`services/insight_jobs.py`); при нескольких репликах API -
  очередь задач (Redis/RQ или Postgres `SKIP LOCKED`) и пул воркеров агента, ход генерации читается из
  `agent_traces` так же, как сейчас.
- **Бюджет**: дневной лимит в `services/token_budget.py` общий для всех процессов (таблица `token_usage`); при
  исчерпании API отвечает 429, лента и готовые разборы продолжают работать.
- **Сбор новостей**: worker с APScheduler; источники независимы, сбой одного не останавливает остальные.
  Для нескольких воркеров - разнести источники по воркерам; дубли отсекаются уникальным `dedup_hash`.
- **Поиск**: BM25 в памяти процесса с перестройкой при изменении таблиц; на миллионах документов - Postgres FTS
  или OpenSearch; колонки `embedding` и HNSW-индексы уже есть на случай разрешённой эмбеддинг-модели.

## Сопровождение качества
- Офлайн-eval (`eval/run_eval.py`) на трёх наборах: synthetic (регрессия логики), real (подбор правок), holdout
  (проверка правок на новостях, которых не было при подборе). Правка ранжирования, промптов или таксономии
  принимается, только если holdout не ухудшился (`docs/ml.md`, раздел 6).
- Онлайн-метрики и обратная связь - `docs/monitoring.md`, экран «Качество AI» в интерфейсе.
